## 3. 검증된 발견 (LANE_SUBMITTED — C 재현 대기)

### HD-01 · 채널이 코드 분포를 만든다 (방법론)
`V1`(가격 정당화 수용)은 65%가 소매 리뷰에서, `V6`(가격 민감도)는 73%가 커뮤니티에서 온다. 커뮤니티는 질문하러 오거나 딜을 찾으러 온 사람이고, 소매 리뷰는 이미 구매한 사람이다.

**본 런 1차에서 "DE는 독립 V1 발화 0건(전부 협찬)"이라 결론냈으나, 소매 리뷰 62행 추가 후 협찬 0건인 독립 `V1`이 11건 나와 자체 반증했다.** 그 결론은 소비자 언어의 부재가 아니라 소스 선택의 산물이었다. → **`V6:V1` 비율을 채널 혼합 코퍼스로 계산하면 안 된다.** 커뮤니티만 5.4:1, 소매만 1:1이며 어느 쪽도 시장 값이 아니다.

### HD-02 · 정량 RTB "24%"는 소비자 언어에 존재하지 않는다
브랜드의 유일한 정량 근거이며 시장마다 표기를 달리해 배포한 수치(US·DE는 글라이드 개선, KR·JP는 마찰 감소)가 **620건 중 0건**이다. 코퍼스가 302→620으로 배증했는데도 0이고, dense 검색 top-20에도 없다. 시장별 표기 3종으로 각각 별도 쿼리를 돌린 결과도 0건.

### HD-03 · 저마찰 편익은 살아 있으나 브랜드 언어로는 검색되지 않고, 카테고리 공통이다
숫자는 없어도 저마찰 **체감**은 4개 시장에서 확인된다. 단 소비자는 이를 마찰·글라이드 어휘가 아니라 **피부 결과 어휘**(자극 없음·아프지 않음·피부가 편함·반복 패스 감소)로 말한다. 어휘 기반 검색이 dense top-20의 **90%를 놓쳤다.**

**그러나 top-20 중 NEVO는 5건뿐이고 나머지는 경쟁 플래그십 사용자다.** → 저마찰 체감은 카테고리 공통 편익이며 NEVO가 소유할 수 없다.

### HD-04 · 소재는 만족의 근거이지 선택의 근거가 아니다
소재 서사를 3층으로 분해해 각각 검정했다.

| 층 | 판정 | 근거 |
|---|---|---|
| 심미(고급감·질감) | 존재 | 제품평 내 언급 확인 |
| 소유(내구·이음매·열화) | 존재, 얇음 | 특정 시장 제품평에 집중 |
| **선택 동인**(그래서 이 제품을 골랐다) | **부재** | 어휘 4건·dense top-20 **0건** |

JP 커뮤니티 대형 스레드 **전수 1,214레스 스캔에서 소재 어휘 0건**이며, 이 패턴이 소매 리뷰 채널에서도 재현됐다(JP 소매 70건 중 소재 특정 언급 1건). dense가 top-20 전부를 새 후보로 가져왔음에도 그 안에 선택 동인 발화가 없다 — **어휘 부족이 아니라 실재하지 않는다.**

**반례 1건:** NEVO 제품평에서 **수지(플라스틱)의 질감을 칭찬**하는 발화가 관측됐다. 「質感」은 재료가 아니라 마감의 문제이며, 소재 서사가 소비자 지각에서 재료 종류와 무관하게 작동함을 시사한다.

**기각된 가설:** 본 런은 초기에 "소비자가 정가가 아니라 역대 최저가를 기준으로 갭을 재계산한다"는 가설을 세우고 최우선 검증을 지시했으나, KR 관련 스레드 20개 전량 + 영상 댓글 101건 전수 스캔 결과 n=2(단일 갤러리·이틀)로 **국지적 현상이어서 기각**했다. 같은 검색이 대신 위 대안지출 프레임을 찾아냈다.

## 4. 의미 기반 그라운딩 (dense embedding 계층)

### 4.1 설계
- 어휘 기준선 `LEXICAL_BASELINE_v1`(TF-IDF, 언어별 분리) **동결**: 가중 정밀도 0.39 · 재현율 0.39 · **κ +0.24**
- Dense: **BAAI/bge-m3** (dim 1024, CLS, L2, fp16), 원문 임베딩이 primary — KO/JA/DE를 영어 번역으로 대체하지 않음
- **임계 기반 분류를 사용하지 않았다.** dense는 후보를 검색하고 판정은 사람이 읽어서 한다

### 4.2 왜 임계를 쓰지 않았나 — 캘리브레이션 실측
검증 쌍 25개(positive 10 / hard-negative 11 / ambiguous 2 / stance-flip 2)를 실측한 결과 분포가 거의 분리되지 않는다.

| | 최소 | 중앙 | 최대 |
|---|---:|---:|---:|
| POSITIVE | 0.450 | 0.608 | 0.845 |
| HARD_NEGATIVE | 0.440 | 0.562 | **0.760** |

**AUC 0.582.** 재현율 100%면 정밀도 0.48, 정밀도 1.00이면 재현율 0.10. 네 코드(소재→소유, 가격정당화, 가격민감, 고장)에서 **hard negative가 positive보다 높은 유사도**를 받았다.

→ 가격 어휘를 공유하되 결론이 반대인 쌍은 의미 공간에서도 가깝다. **유사도로 스탠스를 추론할 수 없다**는 실측 근거이며, 어휘 기준선에서 가격 민감도 코드의 κ가 음수였던 현상이 dense에서도 재현된다.

### 4.4 신뢰성 — 전략 가설의 약화 (본 런에서 가장 중요한 결과)
긍정·부정 centroid를 **각각 독립 검색**했다(단일 centroid로 검색하면 방향이 섞인다).

| 방향 | n(유사도 ≥0.60) | 시장 | 채널 | NEVO |
|---|---:|---:|---:|---:|
| 고장 이웃 | 113 | 4 | 3 | 14 |
| **장수 이웃** | **89** | 4 | 3 | 16 |

**고장 : 장수 = 1.27 : 1.** 거의 균형이다. 4개 시장에서 다년 무고장 사용 발화가 관측되며, 브랜드가 공표한 소모품 교체 주기가 실제로 지켜진다는 소비자 확인도 있다.

→ **"내구성 불신이 지배적"이라는 판단은 고장 쪽만 검색한 결과였다(complaint-search bias).**

**전략 검정 R1~R5**

| | 조건 | 판정 |
|---|---|---|
| R1 | 고장이 독립 소스에 실질 존재 | **PASS** — 113건, 4시장 3채널, 단일 (시장,채널) 집중도 18% |
| R2 | 긍정 장수 역검색이 뒤집지 않음 | **부분 실패** — 89건 존재. 뒤집지는 않으나 "불신 지배" 명제 불성립 |
| R3 | 소유 리스크가 절삭 페인보다 지불의사에 강하게 연결 | **PASS** — 교차표에서 절삭 페인 4종 → 가격정당화 전부 0, 고장 → 가격정당화만 존재 |
| R4 | 단일 포럼 산물 아님 | **PASS** — 최대 집중도 18% |
| R5 | 제품 RTB가 관측된 고장 모드와 기전적으로 연결 | **FAIL** |

**R5 실패 이유:** 지배적 고장 모드가 **전원 버튼**과 **배터리**이며, 금속 일체형 바디는 둘 다 막지 못한다. 하우징·이음매에는 기전적으로 대응하나 실제 고장은 거기가 아니다.

**판정: `CONSUMER_NEED_CONFIRMED` / `PRODUCT_RTB_UNRESOLVED`.** 현 시점에 신뢰성을 마케팅 주장으로 내세우는 것은 권고하지 않는다.

## 6. 방법론 자산 및 정정

### 6.1 대상 문서 결론 반증 — "데스크 크롤링 단독 불가"는 5경로 한정으로만 참
대상 문서는 US 커뮤니티를 n=0으로 닫으며 인증 세션 또는 API 키가 필요하다고 결론냈다. 그 5경로는 본 런에서도 동일하게 실패했으나, **개별 스레드 직접 접근**이라는 6번째 경로 카테고리가 우회한다. 같은 원리가 KR에도 적용됐다(데스크톱 챌린지 → 모바일 도메인).

한 사례에서는 차단이 아니라 **취득기의 오판**이었다 — 챌린지 인터스티셜을 성공으로 통과시키고 있었고, 셀렉터로 성공 기준을 강제하자 실브라우저 경로까지 에스컬레이션해 원문을 회수했다.

### 6.2 리뷰는 서버 HTML에 있는 경우가 많다
대상 문서가 "JS/AJAX 렌더링이라 정적 HTML에 없다"고 판단한 리뷰 상당수가 실제로는 서버 렌더링돼 있었다. 확인된 패턴(사이트명 비공개 아님 — 기법만 기재):

| 패턴 | 대상 |
|---|---|
| 상품페이지 DOM 훅 (데스크톱과 훅 이름이 다름) | 대형 글로벌 커머스 |
| `application/ld+json` 의 Review 배열 | 가격비교 사이트, 미국 전자제품 리테일러 |
| `__NEXT_DATA__` 내 리뷰 페이로드 | 미국 대형 리테일러 2곳 |
| `__INITIAL_STATE__` (배송평과 제품평 키 분리 필요) | 일본 오픈마켓 |
| 리뷰 집계 AJAX 엔드포인트 1개로 14개 오픈마켓 동시 수집 | 한국 가격비교 |

**핵심:** 장벽이 렌더링이 아니라 **엔드포인트 선택**인 경우가 있었다. 전용 리뷰 경로는 로그인 벽이지만 상품페이지에는 리뷰가 서버 렌더링된다.

### 6.3 무결성 사고 — 페이지 요약 도구가 인용을 날조한다
유도성 프롬프트("이 페이지에서 불만을 찾아줘")를 받은 페이지 요약 도구가 **존재하지 않는 사용자 인용을 생성**했다. 두 레인이 각각 자기 산출물에서 발견해 **DE 3건·US 6건을 폐기**했다(원본 HTML 문자열 대조 실패).

**대응:** 인용 추출 프롬프트를 "페이지의 사용자 작성 텍스트를 그대로 옮겨라"로 제한, 소비자 인용은 원본 문자열 대조 필수화, `verification_tier`로 RAW_HTML(567)과 READER_ONLY(53)를 분리. 이후 한 레인은 저장 원본 전량 대조로 날조 0건을 확인했다.

**이 사고는 본 repo의 기존 프로세스 기록(정정 13건 전부 downstream 소비 전 포착)과 같은 계열이며, 상호 감사 루프가 작동한 사례로 기록한다.**

### 6.4 수집 설계 오류 (자체 기록)
오케스트레이터가 검색 결과 상품 ID를 **제품 확인 없이** 수집 타깃에 넣어 오프카테고리 오염이 발생했다 — DE에서 13건(면도기가 아닌 미용기기), JP에서는 배정한 30건 전부가 대상 제품이 아니었다. 담당 레인들이 각각 발견해 제외하거나 재분류했고, 한 레인은 자체 검색으로 올바른 제품 ID를 찾아냈다. **검색 결과 ID는 제목 검증 후에만 타깃에 넣어야 한다.**
